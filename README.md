# Manhwa Discord Cleaner

بوت مستقل لتبييض صفحات المانهوا وإرسال مجلد Google Drive. بنيته Python فقط؛ لا يحتاج Expo أو Qwen أو MongoDB أو خادم HTTP خارجي.

## التشغيل

```bash
python3 -m venv .venv
.venv/bin/pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -e '.[test]'
cp .env.example .env
# ضع بيانات Discord وGoogle Drive في .env
.venv/bin/manhwa-cleaner prepare-models
.venv/bin/manhwa-cleaner doctor
.venv/bin/manhwa-cleaner bot
```

يحتاج البوت صلاحيات View Channel وSend Messages وUse Application Commands. استخدم رابط دعوة بتصاريح `bot` و`applications.commands`. يتطلب Message Content Intent لقراءة المصدر المرسل في القناة وأوامر `!clean`، إضافة إلى Attach Files وRead Message History لتسليم النتائج وتحديث لوحاتها. ضع `DISCORD_GUILD_ID` لتسجيل الأوامر فورًا في خادم معين؛ تسجيل الأوامر العام قد يستغرق بعض الوقت.

* `/clean` أو `!clean`: لوحة البدء الأصلية باللون الذهبي، ثم أزرار الوضع، ثم إرسال المصدر داخل القناة نفسها. `/help` و`!help` يعرضان التعليمات.
* `/clean attachment:` صورة PNG/JPEG/WebP أو ZIP فصل، أو `/clean drive_url:` رابط ملف/مجلد Drive. لا تجمع المصدرين. ترتيب صفحات الفصل طبيعي: 1، 2، 10.
* `mode: dialogue` يبيّض الحوار والسرد داخل الفقاعات، ويعالج النص متعدد الأسطر المعزول على ورق أبيض. يحاول الحفاظ على المؤثرات والواجهات المرسومة.
* `mode: all-text` يمسح النص المكتشف بما فيه المؤثرات والعلامات المائية. اختره فقط إذا أردت ذلك.
* `/status job_id:` حالة محفوظة، حتى بعد إعادة تشغيل البوت.
* `/cancel job_id:` إلغاء مهمة ما زالت في الطابور.
* `/retry_delivery job_id:` إعادة رفع نتيجة محفوظة دون إعادة تبييض الفصل.

## محرك التبييض 2.1

1. تُقرأ الصورة بكامل الدقة، وتُقسّم نوافذ متداخلة في الاتجاهين. يستخدم المسار الافتراضي YOLO11 لتقسيم الفقاعات، وComic Text Detector لتحديد النص، وكاشف PP-OCR مستقلًا لالتقاط الحروف المزخرفة التي قد لا يمكن قراءتها. لا يُشترط نجاح قراءة الكلمة لاكتشافها.
2. تُراجع حدود الفقاعات وتُستكمل الحروف وظلالها وحوافها الفاتحة. توجد معالجة إضافية للفقاعات الداكنة الدخانية وعلامات الحذف والنص المعزول متعدد الأسطر على خلفية بيضاء. حارس الواجهات يحمي تجمعات الملصقات الصغيرة في الرسم.
3. الورق المستوي يملأ بلونه؛ الخلفية المتدرجة تستخدم حقل لون متينًا؛ والخلفيات المعقدة تستخدم Anime-Manga Big-LaMa بقناع متصل يغطي الحروف وظلالها. لا تتغير بكسلات RGB خارج القناع النهائي.
4. يجري فحص قراءة مستقل بعد التبييض. النص المقروء المتبقي أو المنطقة المعروفة التي تعذر إصلاحها يولدان `needs_review`. عبارة `completed` تعني انتهاء الفحص الآلي، ولا تثبت أن كل نص في الصفحة اكتُشف أصلًا. مناطق الاستبعاد محفوظة في التقرير.
5. وضع `all-text` يستخدم المسار العام السابق ولا يملك جميع تحسينات تقسيم الفقاعات الجديدة. المسار الافتراضي المحسّن هو `dialogue`.

هذه تحسينات برمجية فوق نماذج مسبقة التدريب؛ لم ندرّب أوزان نموذج جديد. المصادر واختيارات النماذج موثقة في [quality-research.md](docs/quality-research.md).

المرفقات تعود صورًا بأسماء `-clean.png`، وZIP يعود ZIP، ومصدر Drive يعود مجلد نتائج جديد. يتجاوز الناتج حد Discord فيتحول تسليمه إلى Drive. زرا «سرعة عالية» و«دقة كاملة» يحتفظان بتدفق الواجهة الأصلية؛ كلاهما يستخدم حاليًا محرك الحوار المحسّن نفسه، دون إعادة مسار التبييض القديم الأقل دقة.

كل صفحة ينتج عنها `cleaned.png` و`mask.png` و`overlay.png` و`report.json`. مجلد درايف يحتوي الصفحات النهائية بأسماء 0001.png و0002.png، وتقرير `chapter-report.json` بأسماء المصادر، وأرشيف `review-artifacts.zip` للقناع والمعاينة وتقارير الصفحات. رابط النتيجة قابل للقراءة لمن يملك الرابط.

## الطابور والتسليم

SQLite WAL يحتفظ بالمهام. عامل واحد فقط بوساطة قفل عملية، مع طابور 12 مهمة ومهمة نشطة واحدة للمستخدم. يعاد استئناف المهام بعد انقطاع العامل وتُعاد استخدام الصفحات المكتملة. يفصل فشل التبييض عن فشل Drive. الملف المرفوع يدعم upload resumable وتُفحص أسماء الملفات قبل إعادة التسليم. إشعار الإنجاز يرسل للقناة ليعمل بعد انتهاء صلاحية تفاعل Discord البالغة 15 دقيقة. يبقى `/status` بديلًا عند فقدان صلاحية إرسال الإشعار.

الحدود: 50MB للمرفق/الصفحة، 40 مليون بكسل للصورة، وأقصى عرض 8192 وارتفاع 100000 بكسل، و100 صفحة للفصل، 300MB للصور المضغوطة إجمالًا. تُرفض ZIP المشفرة أو مسارات traversal أو تجاوز حدود فك الضغط. مجلد Drive يدعم الصور وZIP مباشرة، ولا يتتبع المجلدات الفرعية أو الاختصارات.

الصور والنتائج محفوظة محليًا للاستئناف. تنظيف الأعمال النهائية الأقدم من 7 أيام:

```bash
.venv/bin/manhwa-cleaner purge --days 7
```

هذا لا يحذف مجلد النتائج من Google Drive.

## اختبار محلي دون تشغيل البوت

```bash
.venv/bin/python -m pytest tests -q
.venv/bin/manhwa-cleaner clean page.jpg --output data/result --mode dialogue
# قناع يدوي راجعته أنت، مطابق لأبعاد الصورة بعد الاتجاه:
.venv/bin/manhwa-cleaner clean page.jpg --output data/manual --mask text-mask.png
```

CPU يكفي لكنه أبطأ من GPU. الذاكرة تتأثر بأبعاد الصفحة؛ النماذج محملة مرة واحدة داخل عامل واحد. اضبط `CLEANER_THREADS` حسب موارد الخادم. Docker ومشغل Linux موفران في المستودع. استخدام GPU والتقييم الدلالي للفقاعات يحتاجان تطويرًا لاحقًا.

الاعتمادات المثبتة للاختبار مسجلة في `requirements.lock`. أوزان النماذج ثابتة ببصمات تحقق. لإعادة تقييم صفحة كاملة مع سجل تقدم وكشف أولي محفوظ محليًا: `python scripts/evaluate_page.py page.jpg --output data/evaluation`.

للتشغيل كخدمة دائمة على خادمك: عدّل مسار `/opt/manhwa-discord-cleaner` في `scripts/cleaner.service`، ثم ثبّت ملف الخدمة في systemd. التشغيل في بيئة العمل الحالية يستمر ما دامت البيئة نفسها فعالة؛ ليس استضافة دائمة.

## اختبارات منع تراجع الجودة

يحفظ `benchmarks/pages.json` روابط الصفحات وبصماتها، ومناطق النص المطلوبة ومناطق الرسم المحمية. لا توجد إحداثيات خاصة بصفحة في محرك المعالجة. لإعادة تشغيل التقييم الحقيقي بكامل الدقة:

```bash
python scripts/quality_benchmark.py --download --output data/benchmark
# رفض أي تراجع في أهداف اجتازت التقييم السابق:
python scripts/quality_benchmark.py --output data/benchmark-next --compare benchmarks/accepted.json
```

تتحقق البوابة من بقايا اللون في النصوص على الورق، وتغطية أقنعة المناطق المعقدة، وتطابق مناطق الرسم المحمية. إصلاح الخلفية المعقدة يحتاج مراجعة بصرية إضافية؛ تغطية القناع وحدها لا تعني جودة إعادة الرسم. لا يثبت نجاح مجموعة محدودة انعدام الأخطاء لكل الصور المستقبلية. سير عمل Full-page quality gate يشغّل هذه الصفحات عند تعديل محرك الجودة، ويحفظ النتائج والتقارير للمراجعة.

## Google Drive وحدود الصلاحيات

يستخدم البوت اتصال OAuth الأصلي نفسه: `GDRIVE_CLIENT_ID` و`GDRIVE_CLIENT_SECRET` و`GDRIVE_REFRESH_TOKEN`، مع دعم Shared Drives. الرمز الحالي ذو نطاق `drive.file`؛ قد تعيد API رمز 404 لمجلد خارجي رغم أن رابطه العام يفتح. عند 403/404 يحاول البوت قراءة المصدر العام دون تمرير رمز OAuth إلى واجهات الويب. يبقى إنشاء مجلد النتائج والرفع عبر OAuth، بمشاركة عرض لمن يملك الرابط دون فهرسة عامة أو إشعارات بريدية.

المصادر الخاصة لا تصبح قابلة للقراءة بهذا المسار. وصول API إلى مجلدات خاصة خارج الملفات المسموح بها للتطبيق يحتاج اعتماد OAuth بنطاق Drive مناسب؛ مشاركة المجلد وحدها لا توسّع نطاق `drive.file`. المجلدات العامة التي تبلغ 50 عنصرًا أو أكثر تُرفض بدل معالجة قائمة قد تكون مبتورة؛ استخدم ZIP أو اعتماد API مناسبًا للفصول الأكبر. لا تتغير مشاركة المصدر.

اختبار الإصلاح الفعلي: رابط المجلد المبلغ عنه قرئ بنجاح، ونُزّلت صوره الأربع الأصلية بأحجام 800×10195 و800×7003 و800×9650 و760×13500.
