# مراجعة ZEUS: التسجيل وردود الحماية

هذه نسخة مراجعة من `text_bot` في `shsn40328-ux/ZEUS-ex`، فرع `Zeus`،
عند commit `d5caab76d2649a32169abcc184b120780e4ca706`.
المستودع المضيف مستخدم للاختبارات على فرع مستقل فقط، بطلب المستخدم.
لم يتغير `main`، ولم تتغير خدمة Railway أو مستودع المصدر بهذه التعديلات.
لا توجد مفاتيح أو ملفات `.env` أو أصول صور في هذه النسخة؛ ليست حزمة نشر مستقلة.

## ما تأكد من التشخيص

1. `signup_qwen` كان يختبر رمز HTTP فقط. بذلك يُحسب رد HTML ذي الحالة
   `200` كنجاح، ثم ينتظر البرنامج بريد تفعيل لحساب لم يثبت إنشاؤه أصلًا.
2. معظم دوال الحساب كانت تبتلع الاستثناءات. لذلك الرسالة العامة
   «فشل إنشاء حساب جديد بعد عدة محاولات» لا تحدد إن كانت المرحلة بريدًا،
   تسجيلًا، تفعيلًا أو دخولًا.
3. في اختبار بيئة الفحص السابقة، استجاب إنشاء البريد المؤقت بـJSON،
   بينما رد مسار التسجيل في Qwen بـ`text/html` مع علامات `aliyun_waf`.
   جرى ذلك دون بيانات تسجيل حقيقية. هذه قرينة مباشرة على صفحة حماية
   في بيئة الفحص، ولا تثبت أن عنوان Railway أو GitHub محظور.
4. سجل Railway الذي تمت قراءته أكد اتصال Discord ومزامنة الأوامر
   والإيموجيات. لم يحتوِ على تفاصيل فشل إنشاء الحساب.
5. مسار الاختيار السابق قد يصفّر اختيار الحساب عند `RateLimited` ثم
   يختار آخر أو ينشئ حسابًا. هذا سلوك في المصدر، وليس استنتاجًا عن نية المستخدم.

## التغييرات المقترحة

- فحص نوع الرد وبنيته، والحماية، والحدود، وأخطاء المزود، بدل قبول `200` وحده.
- رسائل تشخيص محددة للمرحلة ورمز الخطأ، دون تسجيل محتوى الرد أو بيانات الحساب.
- إبقاء الحساب المحدد عند الحد، والتوقف دون تبديل أو إنشاء بديل.
- إيقاف الإنشاء التلقائي عند غياب حساب أو عند فتح لوحة الإدارة.
- الإبقاء على طلب يدوي واحد لإنشاء حساب واحد؛ فشل التسجيل لا يعيد إنشاء بريد آخر.
- منع إنشاء بديل أثناء مهلة حساب موجود، ومنع مسح المهلة من زر الواجهة.
- قبول توكن دخول في البنية العلوية أو البنية المتداخلة، مع رفض النجاح بلا توكن.
- فك `&amp;` في رابط التفعيل، وتمييز تعطل البريد عن انتهاء مهلة وصوله.
- إبقاء مسارات API على حالها؛ لم تتوفر أدلة كافية لتبديل إصدارها.

صفحة HTML عادية بعد فتح رابط التفعيل لا تثبت نجاح التفعيل؛ لا يُحفظ الحساب
إلا بعد الحصول على توكن دخول صحيح. صفحة الحماية تُوقف العملية مباشرة.

## ما لم يُحل ولم يثبت

هذه التعديلات **لا تزيل حماية Qwen ولا تثبت نجاح إنشاء حساب حقيقي**.
لا يوجد اختبار نجاح حي للتسجيل أو الاستخراج. لم تُنفّذ محاولة تسجيل حقيقية
أو اختبارات شبكة من GitHub Actions. لم يُغيّر مصدر الاتصال أو تُحل تحديات حماية.

أسباب مثل سمعة عنوان المصدر، أو اشتراط تحقق بشري، أو تغيير مسارات التسجيل
أو بنيته تظل فرضيات تحتاج تأكيد المزود أو بيانات فشل فعلية من بيئة التشغيل.
إعادة التشغيل وتغيير `User-Agent` لا تثبت علاجًا لأي منها.

إذا تطلب المزود تحققًا بشريًا فيُستكمل بطريقته المعتمدة. ويمكن الانتقال لواجهة
API موثقة بمفتاح المستخدم. لا يوجد تكامل بديل أو تغيير مزود مطبق في هذا الفرع.

## الاختبارات

```sh
python3 -m unittest discover -s zeus-text-bot-review/tests -v
python3 -m compileall -q zeus-text-bot-review/text_bot zeus-text-bot-review/tests
```

الاختبارات تعمل دون شبكة أو مفاتيح أو قواعد بيانات. تستخدم الدوال الحقيقية
من `bot.py` مع بدائل للاتصال والتخزين، وتتحقق من منع الخطوات اللاحقة عند الفشل.
ملف GitHub Actions الوحيد المضاف يعمل على فرع المراجعة، بصلاحية قراءة فقط،
ولا يشغّل تطبيق المستودع المضيف ولا ينشر أي خدمة. أُضيف شرط في workflow
اختبارات المستودع المضيف لتخطي هذا الفرع التجريبي فقط؛ `main` لا يتغير.

نتيجة الفحص المحلي: نجح فحص الصياغة و32 اختبارًا. تعذر الرفع بالحساب
الأول، ثم وافق المستخدم على استخدام الحساب الآخر `naruto00o9n-max`.
مستودع الاختبار هو `naruto00o9n-max/New-cleanr` والفرع
`fix/zeus-account-diagnostics-20261018`. نتيجة Actions تُتحقق منفصلة
من نجاح هذه الاختبارات محليًا؛ لا يعني أي منهما نجاح تسجيل حي في Qwen.

ملف `account-review.patch` صالح للفحص على commit المصدر المشار إليه:

```sh
git apply --check account-review.patch
```

لم يُطبّق هذا الملف على مستودع المصدر أو خدمة Railway.
